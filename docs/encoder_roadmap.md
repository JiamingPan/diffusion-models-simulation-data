# Encoder Roadmap for CAMELS Generalizability Diagnostics

This repo currently uses two feature spaces for nearest-neighbor
memorization/generalization checks:

1. **PCA features** from normalized CAMELS slices.
2. **SSCD features** from a public copy-detection model.

Both are useful, but neither is the final answer for cosmological fields.

## Current Encoders

### PCA

PCA is a transparent baseline. The scripts flatten normalized \(128 \times 128\)
fields, standardize them, project onto a small number of principal components,
and L2-normalize the resulting vectors. Similarity is cosine similarity in that
PCA space.

Strengths:

- Simple and reproducible.
- Does not require external pretrained weights.
- Easy to debug when a result looks wrong.

Weaknesses:

- Mostly linear.
- Sensitive to normalization, phase, and global amplitude choices.
- A PCA threshold such as `tau=0.6` is not comparable to the SSCD paper's
  `tau=0.6`; PCA needs its own calibration.

Good use:

- Sanity-check trends.
- Compare generated, held-out, and train-real nearest-neighbor behavior.
- Detect obvious copies when the threshold is calibrated high, e.g. `tau=0.95`.

### SSCD

SSCD is a neural image descriptor trained for copy detection in natural images.
For CAMELS fields, the code renders scalar fields as deterministic grayscale
RGB images, resizes them, and computes L2-normalized SSCD embeddings.

Strengths:

- Matches the metric family used in the reproducibility/generalizability paper.
- Designed to detect image-level near-copies.
- Better than pixel MSE for small appearance changes.

Weaknesses:

- Trained on natural images, not cosmological fields.
- Its invariances may not match the physics we care about.
- A high generalizability score means "not a near-copy"; it does not guarantee
  correct one-point statistics, P(k), or physical fidelity.

Good use:

- Paper-style \(GL(\tau) = 1 - P(\max_i \mathrm{sim}(x, y_i) > \tau)\).
- Paired reproducibility curves from same-noise samples generated by different
  models.

## What a Better CAMELS Encoder Should Do

A CAMELS-native encoder should separate three questions:

1. **Copy detection:** is the generated field too close to a training slice?
2. **Physical fidelity:** does the generated field lie on the CAMELS data
   manifold?
3. **Distribution coverage:** does the generated set cover the same variation as
   held-out real fields?

PCA mostly helps with (1) as a baseline. SSCD mostly helps with (1) in a
paper-compatible way. One-point statistics and P(k) help with (2), but they are
aggregate statistics and can look good even when samples are copied.

## Candidate Next Encoders

### CAMELS Self-Supervised Encoder

Train SimCLR, BYOL, DINO-style, or masked-autoencoder features directly on real
CAMELS slices. Use augmentations that are physically defensible:

- rotations and dihedral symmetries,
- small translations or periodic shifts if appropriate,
- mild amplitude/noise perturbations only if they preserve the scientific
  interpretation.

This is the strongest next direction because the feature space learns CAMELS
morphology instead of natural-image semantics.

### Physics Summary Encoder

Use a vector of domain summaries:

- one-point histogram bins,
- radial P(k),
- optionally bispectrum / higher-order spectra,
- Minkowski functionals or peak counts.

This is interpretable and physics-aware, but it is not a direct copy detector:
two visually different fields can share the same summary statistics.

### Wavelet or Scattering Encoder

Use wavelet/scattering coefficients as a deterministic multiscale morphology
descriptor. This is a good middle ground between PCA and a learned encoder:
more nonlinear than PCA, less opaque than a neural network.

### Diffusion-Model Feature Encoder

Extract intermediate UNet activations from the trained score model and compare
features there. This is attractive because the encoder is task-specific, but it
can be biased by the same model being evaluated. It is best used as a secondary
diagnostic, not the primary memorization metric.

### Foundation Vision Encoder

Try DINOv2, CLIP, or other general vision encoders as an external baseline.
These may capture morphology better than PCA, but they are still trained on
natural images and can miss physics-specific differences.

## Recommended Next Experiment

Use the current Fig. 2 sweep with three parallel diagnostics:

1. **PCA tau sweep** as a transparent baseline.
2. **SSCD tau=0.6** for paper-style near-copy comparison.
3. **P(k) and one-point statistics** for physics fidelity.

Then add a CAMELS self-supervised encoder:

1. Train on held-out real CAMELS slices only.
2. Freeze the encoder.
3. Compute generated-to-training nearest-neighbor similarity, held-out-real
   baseline similarity, and train-real leave-one-out thresholds.
4. Replot the Fig. 2 style RP/GL curves in this CAMELS-native feature space.

The important interpretation rule remains:

> "Not copied" is not the same as "good."

A valid final story should show both low near-copy behavior and good physical
statistics.
